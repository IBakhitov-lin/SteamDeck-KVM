# Общая клавиатура и мышь: ПК на Windows ↔ Steam Deck

[English](README.md) · **Русский**

Одна клавиатура и одна мышь на две машины — курсор доходит до края монитора и
продолжает движение уже на экране Deck'а, клавиатура печатает туда же. Ничего
не переподключается и не перепаривается.

**Работает в игровом режиме SteamOS, а не только на рабочем столе.** Deck видит
не программу, а обычную USB-клавиатуру и обычную USB-мышь, созданные прямо в
ядре. Поэтому ввод доходит и до самого Steam, и до запущенной игры, а не только
до рабочего стола.

## Зачем это написано

[Input Leap](https://github.com/input-leap/input-leap) — поддерживаемый форк
Barrier/Synergy — заархивирован 26.07.2026. Его преемник
[Deskflow](https://github.com/deskflow/deskflow) работает хорошо, но, как и все
остальные KVM-программы (Deskflow, [waynergy](https://github.com/r-c-f/waynergy),
[lan-mouse](https://github.com/feschber/lan-mouse)), на стороне КЛИЕНТА отдаёт
ввод композитору рабочего стола. В игровом режиме SteamOS работает `gamescope`,
который таких клиентов к себе не пускает, — поэтому ни одна из них за пределами
рабочего стола не работает.

Этот клиент (`deck-kvm.py`) пишет напрямую в ядро Linux через `/dev/uinput`,
минуя композитор совсем. Есть композитор или нет — ему безразлично.

## Из чего состоит

| Часть | Роль |
| --- | --- |
| Сторона Windows | Сервер [Deskflow](https://github.com/deskflow/deskflow) (протокол Barrier/Synergy) плюс окно-переключатель |
| `deck-kvm.py` | Клиент для Deck'а — только стандартная библиотека Python 3, без зависимостей |
| `SteamDeck-KVM.ps1` | Окно на Windows: одна кнопка «Включить/Выключить» и видимое состояние связи |
| `install-on-deck.sh` | Установщик в один заход: служба systemd, модуль `uinput`, файл настроек |
| Поиск по сети | ПК вещает «я здесь», Deck слышит и подключается сам — адрес настраивать не нужно |
| `verify_kernel.py` | Проверка на настоящем ядре: создаёт устройства и читает события обратно |
| `verify_protocol.py` | Проверка разбора протокола против настоящего сервера Deskflow |

## Установка

### 1. ПК на Windows (машина, чью клавиатуру и мышь делим)

```powershell
winget install --id Deskflow.Deskflow --exact
```

Настройте его сервером — через окно программы или файлом — так, чтобы был **один
экран для ПК и один для Deck'а**. Имена экранов обязаны совпадать с тем, что
попадёт в `/etc/deck-kvm.conf` на Deck'е на шаге 2. Пример `screens.conf`:

```
section: screens
	my-pc:
	steamdeck:
end
section: links
	my-pc:
		right = steamdeck
	steamdeck:
		left = my-pc
end
```

Запустите ярлык **«Общая клавиатура и мышь»** — он лежит в корне папки, копия
на рабочем столе. Откроется окно с одной кнопкой: **Включить** — сервер поднят,
**Выключить** — остановлен. В окне видно, найден ли Deck и подключён ли он.
Кнопка **Свернуть в трей** оставляет приложение работать значком; закрытие окна
выключает сервер.

### 2. Steam Deck

1. Скопируйте всю папку на Deck — флешкой, по `scp`, как удобнее.
2. Переключитесь в режим рабочего стола, откройте **Konsole** и выполните:

   ```bash
   bash ~/Desktop/SteamDeck-KVM/install-on-deck.sh
   ```

   Адрес ПК указывать не нужно: Deck слышит его рассылку по сети и запоминает
   сам. Аргументом адрес передаётся только там, где рассылка не проходит, —
   гостевой Wi-Fi с изоляцией клиентов, разные подсети, VPN на ПК:
   `bash install-on-deck.sh 192.168.1.50`.
3. Если Deck попросит пароль, которого вы никогда не задавали, — сначала
   выполните `passwd`, потом повторите шаг 2.

Готово, и это единственный раз. Клиент поднимается службой `systemd` при каждом
включении, в любом режиме, и сам находит ПК, когда тот включён.

### Как они находят друг друга

ПК раз в две секунды шлёт в свою подсеть короткую строку «я сервер, имя такое-то,
состояние такое-то». Deck её слышит, отвечает одним пакетом — и, если сервер
включён, подключается по адресу из заголовка этого пакета. Адрес ПК нигде не
прописан: сменился адрес в роутере — ничего не ломается.

Порядок именно такой (вещает ПК, слушает Deck), потому что обратный потребовал бы
входящего правила брандмауэра Windows, то есть прав администратора при установке.
Исходящая рассылка правила не требует вовсе.

## Как пользоваться

| Действие | Как |
| --- | --- |
| Начать работу | Включить Deck, открыть окно на ПК, нажать **Включить** — связь поднимется сама |
| Выключить | Нажать **Выключить** в том же окне — Deck отсоединяется |
| Перейти на Deck | Довести курсор до общего края экрана и задержать там |
| Перепрыгнуть на Deck сразу | **Win+Shift+D** — или та клавиша, что задали в `screens.conf` |
| Вернуться обратно | **Win+Shift+W** либо противоположный край экрана |
| Открыть журнал на Windows | Кнопка **Журнал** в окне |
| Оставить работать без окна | Кнопка **Свернуть в трей**; двойной клик по значку возвращает окно |
| Закрыть совсем | Закрыть окно — сервер останавливается вместе с ним |

## Чего эта связка не делает

- **Общего буфера обмена нет.** Скопированное на одной машине не вставится на
  другой: буфер живёт в графической оболочке, а этот инструмент работает мимо
  оболочки намеренно — ровно этим и куплена работа в игровом режиме.
- **Перетаскивания файлов между экранами нет** — по той же причине.
- Клавиатура и мышь всё время остаются рабочими на ПК; они «уходят» только пока
  курсор на стороне Deck'а.

## Настройка

**Deck слева, а не справа.** Поменяйте местами `right` и `left` в своём
`screens.conf` на стороне Windows и перезапустите сервер кнопкой в окне.

**У ПК сменился адрес.** Ничего делать не нужно — адрес берётся из рассылки, а не
из настроек. Прописанный вручную адрес правится там же, где и задавался:

```bash
sudo nano /etc/deck-kvm.conf   # server=auto — искать по сети
sudo systemctl restart deck-kvm
```

**Deck не находит ПК.** Обе машины должны быть в ОДНОЙ сети Wi-Fi, а сеть не должна
изолировать клиентов друг от друга (в гостевых сетях изоляция включена всегда).
Мешать может и VPN на ПК, если он заворачивает на себя весь трафик. На этот случай
адрес задаётся вручную: `server=192.168.1.50` в `/etc/deck-kvm.conf`.

**Курсор прыгает или попадает не туда.** Переключите указатель в относительный
режим: строка `pointer=rel` в `/etc/deck-kvm.conf`, затем
`sudo systemctl restart deck-kvm`. По умолчанию стоит `pointer=abs` — положение
задаётся абсолютными осями, и ускорение указателя его не искажает; `rel` нужен,
только если `abs` повёл себя странно именно на вашей сборке.

**Проверить, что сторона ядра работает** — прямо на Deck'е:

```bash
sudo python3 ~/Desktop/SteamDeck-KVM/verify_kernel.py
```

Скрипт создаёт виртуальные клавиатуру и мышь, шлёт события и читает их обратно
из ядра. Все строки должны быть `OK`.

**Проверить разбор протокола** — работает на любой из машин, прав не требует:

```bash
python3 ~/Desktop/SteamDeck-KVM/verify_protocol.py
```

**Убрать автозапуск службы** (запускать вручную, когда нужно):

```bash
sudo systemctl disable deck-kvm
sudo systemctl start deck-kvm   # только на этот сеанс
```

В простое служба занимает около 15 МБ памяти и повторяет попытку соединения раз
в 15 секунд — на время работы Deck'а это не влияет.

## Если не соединяется

| Признак | Причина и что делать |
| --- | --- |
| В журнале Deck'а «нет связи» | Значок в трее на ПК серый — кликните, чтобы включить сервер |
| То же, но значок цветной (сервер работает) | На ПК поднят VPN и уводит маршруты. Отключите и проверьте снова |
| Курсор не переходит за край экрана | Deck не подключился — смотрите его журнал |
| Курсор переходит, но клики и клавиши не проходят | Служба на Deck'е работает не от root — переустановите |

Журнал на Deck'е:

```bash
journalctl -u deck-kvm -f
```

Журнал на Windows: правая кнопка по значку → **Открыть журнал**, либо файл
`%LOCALAPPDATA%\SteamDeck-KVM\tray.log`.

## Как это устроено

ПК держит сервер Deskflow: он следит за курсором у края экрана и шлёт события
ввода по TCP, порт 24800. Deck держит `deck-kvm.py` — написанный с нуля клиент
того же протокола (семейство Barrier/Synergy): он разбирает события и
воспроизводит их через `/dev/uinput` двумя виртуальными устройствами ядра —
«Deck KVM Keyboard» и «Deck KVM Mouse». Мышь заявляет и абсолютные оси
(положение курсора), и относительные (обзор и прицел в игре, когда курсор
захвачен); клавиатура умеет нажатие, отпускание и автоповтор на уровне ОС.

Адресация — обычное TCP-соединение, а не поиск по сети: клиент на Deck'е сам
звонит по адресу из `/etc/deck-kvm.conf`, сервер просто слушает порт и принимает
того клиента, чьё имя экрана совпало с его настройкой. Работает только внутри
одной локальной сети; соединение **не шифруется** — не запускайте это нигде,
кроме доверенной домашней сети.

## Удаление (сторона Deck'а)

```bash
bash ~/Desktop/SteamDeck-KVM/uninstall-from-deck.sh
```
